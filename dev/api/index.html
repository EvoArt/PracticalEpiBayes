PracticalEpiBayes.Interweave — Type
Interweave(params, step; field, elements = nothing, radius = Inf, scale = 0.05, centred = 0.05, n = 3)

Joint moves of some parameters and a Field's paths, for a parameter that sets the scale of the steps between an individual's consecutive elements: e.g. a movement scale and the activity centres it links. One at a time, each mixes slowly, because a narrow step scale pins the paths and the paths pin the scale. Interweaving the centred and non-centred forms (Yu and Meng

  1. moves them together.

Each sweep, after the latents, n rounds of:

  • a centred update: a random walk (sd centred) on each of params, the paths held;
  • a non-centred update: u ~ N(0, scale^2), the parameters moved by step(values, u), and every individual's steps between its elements in use multiplied by exp(u) (each path anchored at its first element in use). elements(i), optional, gives the elements of individual i to scale instead of every element in use, e.g. only the ones the likelihood reads. With radius = c, each step of length r is stretched along its direction by the flow of dr/du = r / (1 + (r/c)^2) for time u instead: steps much shorter than c by about exp(u), steps much longer than c hardly at all. Use it when the parameter scales the short steps only, e.g. a resident movement scale when some steps are long dispersals.

step(values, u) returns (new, logjac): a NamedTuple of the new values of params, and the log Jacobian of that map in the parameters' sampled coordinates. Return nothing to reject. Both updates are Metropolis steps on the full log joint plus the paths' own priors, so the model is unchanged. The sds adapt during warm-up.

The parameters named here belong to the latent block, so leave them out of the HMC blocks.

PracticalEpiBayes.LatentBlock — Type
LatentBlock(data)

Placeholder distribution for a LatentHMMData model's latents, held as one LatentState. Declared discrete so PracticalBayes keeps it in the value store, constant to the HMC blocks; its logpdf is zero because the latent priors are scored by the likelihood and the sampler.

@model function m(data, mll)
    p ~ Beta(1, 1)
    L ~ LatentBlock(data)
    @addlogprob! mll((; p), data, L)
end

PracticalEpiBayes.ParamSelector — Type
ParamSelector(names)

Selects names out of the Gibbs state into a NamedTuple — what iffbs_kernel's params = (:a, :b, ...) form builds.

A callable struct rather than a closure so names lives in the TYPE and the NamedTuple construction is fully inferred. This runs once per sweep, but its result is read for every individual at every timepoint, so an abstractly-typed parameter tuple would be expensive in exactly the way EpidemicTrajectories' CLAUDE.md warns about.

PracticalEpiBayes.TrajectoryLatent — Type
TrajectoryLatent(n_time, n_ind)

A placeholder discrete matrix distribution for the whole hidden trajectory X. Its logpdf is a constant 0.0 and its rand is an all-first-state matrix: the trajectory's real conditional is supplied by the iFFBS likelihood term and its real draw by iffbs_kernel. Declaring it Discrete is what makes PracticalBayes route X to the value store (owned by the Gibbs kernel, never touched by NUTS) rather than to the continuous sampler.

PracticalEpiBayes.capture_prob_kernel — Method
capture_prob_kernel(name; caught, effort, group, index, dead_state, n,
                    prior=(1, 1), available=nothing)

Conjugate Beta kernel for a per-index capture/detection probability (the badger etas): the chance an available individual is actually caught. One Beta is drawn per index k ∈ 1:n and the draws are collected into a length-n vector.

An individual is available at (t, i) when it is being trapped (effort[group[i, t], t] == 1, group > 0) and not dead (X[t, i] != dead_state), and caught when additionally caught[t, i] == 1. index[t] selects which of the n probabilities applies at time t (e.g. data.season).

available, if given, is a predicate (X, data, i, t) -> Bool replacing the default "not dead" test, for models whose availability is more than one state.

PracticalEpiBayes.check_step_sizes — Method
check_step_sizes(eps::StepSizes, block_names; lengths=NamedTuple())

Assert that eps was built for exactly block_names, in that order. Throws a message naming the discrepancy otherwise.

The metric is a flat vector, so a mismatch between it and the block's name order is not a type error — it silently assigns one parameter's step size to another. This is the check that turns that into a failure.

PracticalEpiBayes.hmc_block — Method
hmc_block(eps, n_steps)

The fixed-trajectory HMC kernel used with a hand-tuned diagonal metric: HMC(n_steps; integrator=Leapfrog(1.0), metric=DiagEuclideanMetric(eps .^ 2)).

n_steps should match the EXPECTED trajectory length you are targeting, not a nominal maximum — the C++ badger reference draws L uniformly on 1..30 (mean 15.5), so a fixed L = 30 does 1.8x the work for no added fidelity.

PracticalEpiBayes.hmc_step_sizes — Method
hmc_step_sizes(pairs...; lengths=NamedTuple())

Build the flat step-size vector for an HMC block's diagonal metric, from :name => step pairs given in the block's own order.

A vector-valued parameter needs its length, either as :name => (step, n) or via lengths = (; name = n). Passing a per-element vector (:name => [s1, s2, s3]) works too and fixes the length from it.

The result is the concatenation in the order the pairs are given, which must be the order of the block's names in Gibbs — that ordering is the thing this function exists to make explicit rather than implicit.

eps = hmc_step_sizes(
    :tau => 0.002, :alpha => (0.2, n_groups), :lambda => 0.01, :beta => 0.05,
    :q => 0.05, :c1 => 0.02, :a2 => 0.001, :b2 => 0.001,
    :thetas => (0.005, n_tests), :rhos => (0.005, n_tests),
    :phis => (0.005, n_tests))

block = (:tau, :alpha, :lambda, :beta, :q, :c1, :a2, :b2, :thetas, :rhos, :phis)
spl = Gibbs(block => hmc_block(eps, 15), ...)

Use check_step_sizes to assert the result lines up with the block's names before sampling.

PracticalEpiBayes.initial_state_kernel — Method
initial_state_kernel(name; at, eligible, states, prior, n=1, collect=nothing)

Conjugate Dirichlet kernel for the initial-state mixing of newly-entering individuals (the cattle ν, the badger nu). For each of n entry times, it counts how many eligible individuals start in each of states and draws the mixing proportions from Dirichlet(prior).

  • at — a single time index (n=1) or, for n > 1, a vector of n entry times.
  • eligible — predicate (X, data, i, t) -> Bool selecting the contributing individuals at cohort time t.
  • states — state indices whose counts form the Dirichlet categories, ordered to match prior.
  • collect — assembles the n probability vectors into the block value. The default covers both real cases with no configuration:
    • n == 1, two states → the scalar P(states[2]) (the cattle ν = P(I));
    • n == 1, more states → the single probability vector;
    • n > 1 → an n × (length(states) − 1) matrix of the non-reference components (the badger (nuE, nuI) layout: the first state is the implied 1 − Σrest).
    Pass your own collect to override.

PracticalEpiBayes.interweave_kernel — Method
interweave_kernel(sampler, iws::Interweave...; n_adapt = 0, params = nothing)

The Gibbs kernel for a LatentBlock together with one or more Interweaves' parameters: sampler (from epidemic_latent_sampler(data)) updates the latents, then each Interweave in turn moves its parameters and the paths. List the block first, then every parameter once: (:L, iw.params...) => interweave_kernel(smp, iw; n_adapt). params is as for latent_kernel; n_adapt the number of sweeps over which the interweaving step sizes adapt.

PracticalEpiBayes.latent_gibbs — Method
latent_gibbs(data, blocks...; n_adapt = 0, seed = 1, interweave = nothing)

The Gibbs sampler for an @latent_model: the latents updated by epidemic_latent_sampler(data) (whose proposal scales adapt over the first n_adapt sweeps), then each block as given, e.g. (:a, :b) => AdaptiveHMC(0.8; n_leapfrog = 10). With an Interweave (or a tuple of them), the latent block also owns their parameters and interweaves them with the paths.

PracticalEpiBayes.test_sensitivity_kernel — Method
test_sensitivity_kernel(name; Y, infected_state, prior=(1, 1))

Conjugate Beta kernel for a diagnostic test's sensitivity — the probability a truly-infected individual tests positive. Y[t, i] is the result matrix (1 positive, 0 negative, negative = not tested); infected_state is the state index counted as infected (2 for S/I, an SEID I, etc.); prior is the Beta(a, b).

Assumes perfect specificity (susceptibles never test positive), so only infected tested cells contribute — the closed form behind the cattle TestSensKernel. For a test with imperfect specificity, resample sensitivity and specificity with separate kernels over the appropriate cells.

PracticalEpiBayes.@conjugate — Macro
@conjugate name ~ Beta(a, b) count_body
@conjugate name ~ Dirichlet(αs) count_body
@conjugate name[1:n] ~ Beta(a, b) count_body

Build a conjugate Gibbs kernel for the block name in one expression, without the struct-plus-gibbs_step boilerplate. Expands to a PracticalBayes ConjugateGibbs kernel you drop straight into Gibbs.

The ~ line names the block and its conjugate prior. count_body is ordinary Julia with X and data in scope — the current trajectory (a Matrix{Int} indexed X[t, i]) and the EpidemicData — that must return the counts the family expects:

  • Beta → (successes, failures)
  • Dirichlet → a vector of category counts (same length as αs)

The vector form name[1:n] runs the body once per index k ∈ 1:n (with k in scope) and collects the n draws into a vector.

Example — a test's sensitivity (cattle θʳ)

θʳ = @conjugate θʳ ~ Beta(1, 1) begin
    pos = neg = 0
    for t in axes(data.rams, 1), i in axes(data.rams, 2)
        y = data.rams[t, i]
        (y < 0 || X[t, i] != 2) && continue   # untested, or not infected
        y == 1 ? (pos += 1) : (neg += 1)
    end
    (pos, neg)
end
# ... spl = Gibbs(:θʳ => θʳ, ...)

Example — capture probability per season (badger etas, vector-valued)

etas = @conjugate etas[1:NS] ~ Beta(1, 1) begin
    caught = available = 0
    for t in axes(X, 1)
        data.season[t] == k || continue        # `k` is the season index
        for i in axes(X, 2)
            g = data.social_group[i, t]
            (g > 0 && data.capt_effort[g, t] == 1 && X[t, i] != 4) || continue
            available += 1
            caught += data.capture[t, i] == 1
        end
    end
    (caught, available - caught)
end

PracticalEpiBayes.@latent_model — Macro
@latent_model function name(data, args...)
    a ~ Beta(1, 1)
    b ~ filldist(Normal(0, 1), 3)
    ...
end

A PracticalBayes model for the LatentHMMData model data (the first argument). Write the priors; the macro adds latents ~ LatentBlock(data) and the marginal log likelihood given every parameter declared with ~ at the top level of the body. Sample it with latent_gibbs.
